# Skill: разбор TLS-инцидентов

Агент получает список «подозрительных» доменов от быстрой проверки (без AI)
и обязан подтвердить находки, классифицировать их, сохранить отчёт и завести issue.

## Порядок действий

1. Для КАЖДОГО домена из входных данных вызови `check_tls` и убедись, что находка воспроизводится.
   Если не воспроизводится, пометь как «не подтверждено» и issue не создавай.
2. Если домен основной (apex, например `example.com`, а не `api.example.com`), вызови `check_domain_expiry`.
3. Если сертификат невалиден по подозрительной причине (чужой издатель, неожиданная смена)
   или нужно исключить чужой выпуск, вызови `query_ct_logs`.
4. Классифицируй каждую проблему как critical / warning / info по правилам ниже.
5. Сформируй отчёт в Markdown и сохрани его через `write_file` в `/data/reports/YYYY-MM-DD.md`
   (дата берётся из входных данных).
6. Для critical и warning вызови `create_issue` (по одному на домен). Для info issue не создавай.
7. Верни итоговое сообщение для дежурного (формат ниже).

## Правила классификации

- **critical**: сертификат истёк; не проходит проверка (не тот домен, самоподписанный,
  недоверенный корень, битая цепочка); ошибка соединения; домен (регистрация) истёк;
  в CT-логах свежий сертификат от неожиданного издателя.
- **warning**: до истечения сертификата или домена 14 дней и меньше.
- **info**: плановая смена сертификата при ожидаемом издателе; домен жив, но RDAP недоступен.

Ожидаемые издатели: Let's Encrypt, Google Trust Services.

## Runbook (кратко, что рекомендовать)

- Сертификат истёк или скоро истечёт: проверить, почему не сработало автообновление
  (certbot/acme-клиент, DNS-проверка, права на файлы), выпустить новый, перезагрузить веб-сервер.
- Не тот домен / цепочка: проверить, что выдан сертификат на нужное имя и подгружен fullchain.
- Самоподписанный / недоверенный корень: заменить на сертификат публичного CA.
- Чужой издатель в CT-логах: считать возможной компрометацией. Перевыпустить сертификат
  с НОВЫМ ключом, отозвать старый, проверить доступы к DNS и аккаунту CA.
- Домен скоро истечёт: продлить у регистратора, проверить привязку карты и контактный email.

## Формат issue

- репозиторий: owner=`KenyaProgressive`, repo=`itmo-devops-labs` (всегда передавай эти значения в `create_issue`).
- title: `[TLS][critical|warning] <домен>: <краткая суть>`
- body: что найдено, подтверждение (какие tools вызваны и что вернули), рекомендуемые шаги из runbook.
- labels не указывать.

## Формат итогового сообщения (plain text, до 10 строк)

```
TLS-проверка <дата>
critical: <N>, warning: <N>, info: <N>
- <домен>: <суть> -> <issue URL или "issue не создан">
Отчёт: /data/reports/<дата>.md
```

## Ограничения

- Не делай выводов без подтверждения вызовом tool.
- Не меняй инфраструктуру и не перевыпускай сертификаты, только рекомендуй.
- Не создавай больше одного issue на домен за запуск.
- Если tool вернул ошибку, укажи это в отчёте, а не придумывай результат.
- Не выводи в ответ приватные данные, токены и ключи.
